# DESIGN

## 1. Отмена устаревших запросов

Проблема: пользователь печатает `ru`, потом `russia`. Ответы могут прийти в другом порядке, и поздний ответ на старый запрос `ru` затрёт результат на `russia`.

Решение: `createLatestSearch` (`src/latestSearch.ts`) хранит в замыкании `AbortController` предыдущего запроса. При каждом новом поиске:

1. вызывается `abort()` для старого запроса;
2. создаётся новый `AbortController`;
3. отправляется новый запрос с его `signal`.

Старый `fetch` отклоняется с `AbortError`, интерфейс (`runSearch` в `src/main.ts`) его молча игнорирует. Если пользователь стёр поле целиком, вызывается `search.cancel()`: иначе ответ на последний запрос пришёл бы уже в пустой список.

Почему именно так, а не флагом вроде «этот ответ актуальный?»: флаг только прячет устаревший ответ, а сам запрос идёт до конца. Он впустую занимает сеть и сервер, а в Network tab выглядит как успешный. `abort()` прерывает сам запрос (в Network он `canceled`), и устаревший ответ вообще не приходит. Не нужно хранить номера запросов или метки времени.

Таймаут: `AbortSignal.timeout(10000)` объединён с сигналом отмены через `AbortSignal.any`. Запрос один, а оборвать его можно двумя способами, и они различаются по имени ошибки: `AbortError` — мы отменили сами (ничего не показываем), `TimeoutError` — сервер не ответил (показываем «Сервер не отвечает» и кнопку «Повторить»).

## 2. Задержка debounce 300 мс

`debounce` (`src/debounce.ts`) откладывает поиск, пока пользователь не перестал печатать на 300 мс. Таймер сбрасывается при каждом нажатии.

- Если убрать задержку, на каждую букву уходит запрос: лишняя нагрузка на сервер, мигание списка и «Загрузки…», а защита от гонки работает постоянно.
- Если поставить слишком большую (например, 5 секунд), приложение будет казаться сломанным: пользователь напечатал слово и ничего не происходит.
- 300 мс — компромисс: пауза между словами уже заметна как «закончил печатать», но результат появляется почти сразу.

Debounce и отмена дополняют друг друга: debounce уменьшает число запросов, а отмена гарантирует, что оставшиеся запросы не перепутают порядок.

## 3. Сложность

`mapCountryResponse` (`src/mapCountryResponse.ts`) выполняет фиксированное число присваиваний и один `map` по языкам страны, то есть работает за O(L), где L — число языков одной страны (на практике несколько штук, поэтому почти O(1)). Для списка из n стран получается O(n · L): каждая страна обрабатывается один раз. Дополнительная память — O(L) на карточку.

## 4. Принципы чистого кода

- **Разделение ответственности.** Логика поиска не знает про DOM: `debounce.ts`, `searchCountries.ts`, `mapCountryResponse.ts`, `httpError.ts`, `latestSearch.ts`. Она тестируется без браузера и без сети (`fetch` подменяется в тестах). Всё про DOM живёт только в `src/main.ts`.
- **Одна функция — одна задача.** `createCardElement` строит карточку, `showDetails` — детальный вид, `runSearch` запускает поиск и обновляет экран, `mapCountryResponse` только преобразует данные.
- **Нет дублирования.** Одна `runSearch` обслуживает и ввод (через `debounce`), и кнопку «Повторить».
- **Своя ошибка вместо «магических» проверок.** `HttpError` хранит статус, а виды ошибок различаются по `error.name` в одном месте (`catch` в `runSearch`).
- **Ранний выход вместо вложенности.** `return` для пустого ввода и для `AbortError`.
- **Говорящие имена.** `createLatestSearch`, `searchCountries`, `showDetails`, `timeoutMs`, `retry`.
